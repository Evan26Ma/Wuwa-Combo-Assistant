# OK-WW 操作规则映射

本项目只借鉴 OK-WW 的角色状态判断和动作优先级，不复制其输入发送逻辑，也不会因此向《鸣潮》发送任何输入。视频文字轴仍是按键顺序的唯一来源；OK-WW 规则只作为每一步的操作解释和资源检查建议。

分析基于用户本机 OK-WW 提交 `ab38a5eeed9466f7da238261c0a3cb3e8e42e62b`：

- `src/char/Cartethyia.py`：三剑资源、落地检查、空中攻击、小卡提变身和大形态终结。
- `src/char/Ciaccona.py`：变奏普攻、跳 A、三格重击、E/R/Q 顺序及卡提队切人限制。
- `src/char/Chisa.py`：支援增益、Q/R/E 优先级、空中等待和满资源长按 E 重击。
- `src/char/Suisui.py`：普攻/E 积累 Forte3、R 后补满协奏及切人锁定。
- `src/char/YangYangSp.py`：持续长按普攻，R 优先于 E，E 稳定可用后再触发。

当 OK-WW 通用轮转与教学视频轴不一致时，界面会明确提示“按当前轴执行”，不会自动更改或跳过视频步骤。

## 动画期间的输入保护

OK-WW 对大招动画的通用判断位于 `BaseChar.click_liberation()`：释放后等待 `in_team()[0]` 变为假，表示队伍 HUD 随演出隐藏；随后持续推进画面帧，直到队伍 HUD 再次出现。`BaseCombatTask.send_key_and_wait_animation()` 也使用“条件由真变假再恢复”为动画开始/结束信号，并用总超时防止卡死。

OK-WW 并不通用识别每一段普攻动画的结束帧。角色脚本通常使用约 0.1 秒点击间隔和角色专属持续时间，例如穗穗 `ATTACK_INTERVAL = 0.1`，再通过技能、回路或协奏 HUD 决定后续动作。

本项目据此实现只读 `AnimationInputGuard`：

- 按下 `R` 后暂停状态机推进；近期能稳定看到队伍 HUD 时，需要连续两帧 HUD 消失才确认进入演出，并在连续两帧恢复后解锁。
- HUD 识别不可用时使用默认 3000ms 大招保护；识图演出最长 8000ms 后强制解锁，避免永久卡死。
- 普攻默认只使用 110ms 短保护，不宣称识别实际动画结束帧。
- 保护期间程序仍只轮询物理按键，不拦截、不吞键；这些输入仅不提交给连招状态机。`ESC / F8` 重置不受保护影响。

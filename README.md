# 鸣潮合轴辅助助手 · 零额外按键逐键教练

> [!WARNING]
> 本项目仍处于公开测试阶段（Beta），仅供学习与交流，禁止商业售卖或用于任何收费服务。仓库及发布的 EXE 完全免费。连招数据、角色识别和不同分辨率下的表现仍在持续验证，请勿把提示结果视为绝对准确。

一个面向 Windows 的《鸣潮》只读连招提示工具。玩家照常操作游戏，程序监听已配置的真实按键，自动推进连招，并用透明置顶悬浮窗显示角色分段轴地图。

程序不会拦截、修改或模拟游戏输入，不会自动战斗，也不上传截图和按键记录。

## 当前功能

- 启动轴执行完成后自动进入循环轴，无需额外脚本热键。
- 真透明战斗 HUD 支持横向、纵向、瀑布三种角色分段地图；不铺设背景面板，只保留头像、按键、轴名和状态描边，同一轴段最多显示 6 个动作。
- 主地图最多展开当前附近 3 个轴段，顶部节点条保留整轴位置、已完成段、当前段和剩余段，地图随操作自动平移。
- 当前错误会直接标红到对应招式块，正确输入后自动清除。
- 悬浮层提供“移动模式”；关闭后鼠标穿透，不阻挡游戏点击。
- 悬浮 HUD 可在“提示设置”中按 65%–150% 等比调节，头像、按键、文字和轴段间距实时预览。
- 默认按 `F7` 可临时隐藏/恢复战斗 HUD；不暂停监听或连招进度，可在“键位设置”改键、在“提示设置”关闭该快捷键。
- `A` 表示鼠标左键普攻，`Z` 表示长按左键重击；仅是显示记号，不会改变游戏键位。
- 监听普攻、长按重击、`E / Q / R`、跳跃、闪避以及三个队伍槽位。
- 根据识别到的队伍顺序，把“切换到某角色”换算为实际的 `1 / 2 / 3`。
- 队伍角色卡可以拖动排序；所有切人动作按目标角色自适应为当前槽位键。
- 普通错键不会停止程序；唯一性较高的角色、技能和输入组合可辅助恢复连招位置。
- 动作保护会在普攻短后摇和大招演出期间暂停连招推进：大招优先通过队伍 HUD 消失/恢复判断，无可靠识图时使用可调兜底时长；`ESC / F8` 重置始终有效。
- `ESC` 或 `F8` 可随时重置到启动轴第 1 步，两个键都能在设置中修改。
- 可查看完整启动轴、循环轴和当前进度。
- 可选 HUD 识别用于角色判断、队伍排序与锚点评分，识别失败不会阻止按键推进。
- 连招使用结构化 JSON，启动轴、循环轴、角色、动作语义和显示文字相互独立；`a/z/e/q/r/i/ii/iii` 的文字与图标映射也单独维护。
- “视频识别”页可从本地教学视频的标准青色按键面板提取候选时间轴；输出必须人工复核，不会直接覆盖内置连招。
- 所有设置、键位和校准数据保存在 `%APPDATA%\WuwaComboAssistant`。

## 已内置连招

| 队伍 | 流程 | 教学来源 |
|---|---|---|
| 卡夏千 | 启动轴一次 → 自动循环 | [卡夏千 30s 标准双下落进阶轴](https://www.bilibili.com/video/BV1i8QpBQEQ4/) |
| 秧千穗 | 约 28 秒启动轴一次 → 约 25.3 秒循环 | [秧千穗双羽轴教学](https://www.bilibili.com/video/BV1YYGA6hExX/) |

连招步骤以教学视频整理出的按键轴为准。当前版本只做按键辅助，不宣称能够准确判断每一次命中、落地动画或最佳输入帧。

## 下载与启动

仓库内已提供便携版：[`dist/鸣潮逐键教练.exe`](dist/鸣潮逐键教练.exe)。无需安装 Python。

1. 右键 EXE，选择“以管理员身份运行”。
2. 首次启动会进入“键位设置”，确认实际游戏键位并保存。
3. 选择队伍和连招，打开《鸣潮》后正常操作即可。
4. 游戏位于前台时，悬浮窗会显示当前附近的角色轴段，并在整轴节点条中自动跟随当前位置。

> [!IMPORTANT]
> 如果《鸣潮》以管理员权限运行，普通权限的辅助程序无法读取游戏内按键。遇到“游戏里按键但悬浮窗没反应”，请先确认本程序也已使用管理员权限启动。

### 常用操作

| 操作 | 方式 |
|---|---|
| 重置当前连招 | `ESC` 或 `F8` |
| 临时隐藏/恢复悬浮窗 | `F7`（可改键或关闭） |
| 查看全部按键 | 悬浮窗“全部按键”或控制台“完整按键轴” |
| 修改游戏键位 | 控制台“键位设置” |
| 手动选择队伍 | 控制台“队伍选择” |
| 调整悬浮窗 | 控制台“提示设置” |
| 移动/穿透悬浮窗 | “提示设置”、悬浮窗右键菜单或托盘菜单 |
| 提取视频候选轴 | 控制台“视频识别”，选择本地视频并校准按键面板区域 |
| 隐藏到托盘 | 控制台或悬浮窗右键菜单 |

`ESC` 只会被程序读取，不会被吞掉，因此游戏菜单仍会正常打开；不希望同时打开菜单时可使用 `F8`。

## 画面识别

画面识别属于可选增强功能，不是连招推进的硬条件。目前内置：

- 卡提希娅、夏空、千咲、秧秧、穗穗的角色 HUD 模板。
- 卡提希娅三剑、形态、空中攻击、终结解放等状态模板。
- 穗穗 Forte3 状态模板。
- 三个队伍栏位的连续帧确认和排序记忆。

不同分辨率、DPI、画质、色彩设置以及复杂特效都可能降低识别准确率。可在“画面识别”页重新选择 HUD 区域、采集模板或关闭识别。

## 测试阶段说明

当前版本适合体验和协助测试，尚不代表稳定发布版。已知边界包括：

- 内置连招只覆盖上述两支队伍，且仍需继续实战核对。
- 监听只能看到物理按键状态，无法保证理解游戏内部是否真正接受了该次输入。
- 快速连点、帧率波动、卡顿、切出游戏和自定义键位可能导致短暂不同步。
- 角色与 HUD 识别可能出现漏判，程序会保守沿用上一次结果，而不是强制跳轴。
- 普攻没有稳定的通用 HUD“动画结束”信号，因此默认仅使用 110ms 短保护；可在“提示设置”调整或关闭，不能保证适配所有角色的取消窗口。
- 未签名 EXE 可能触发 Windows SmartScreen 提示。
- 第三方辅助工具可能受游戏服务条款限制，请在使用前自行确认当前规则并自行承担使用风险。

提交问题时请提供 Windows 版本、屏幕分辨率/DPI、游戏键位、所选队伍、复现步骤和问题截图。请勿上传账号信息或其他敏感数据。可使用仓库的 Bug Report 模板。

## 从源码运行

需要 Python 3.11 或更高版本：

```powershell
python -m pip install -r requirements.txt
.\run.ps1
```

运行测试：

```powershell
python -m pip install -r requirements-dev.txt
python -m pytest -q
```

构建单文件 EXE：

```powershell
.\build.ps1
```

构建脚本会先运行测试，再使用 PyInstaller 生成 `dist\鸣潮逐键教练.exe`。
